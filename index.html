Automated Rating-Call Pipeline

Urban Piper unmasks the customer's number, then Exotel auto-dials and plays a 30-second rating ask.
Every outcome — answered or not — is logged into one success-rate view. No live agent required.

Current state — across all brands

Four mechanisms in use today

  1. Bridge number with order manual
    The kitchen team calls the customer during a short window around order delivery, asking for a 5★ rating.
    Zomato: 30-minute window post order delivery — the bridge number must be requested before dispatch or the option disappears.
    Swiggy: 30-minute window post order delivery, bridge number comes with a PIN entered after dialling; up to 2 customer calls per order.
  2. Escalation / customer connect request rarely used
    For post-order issues, ops can request a bridge number and calling slot directly from the Swiggy/Zomato POC to follow up with a customer. Used only occasionally.
  3. Swiggy owner app (Already rated orders) native feature
    Lets any brand call customers who rated in the last 90 days, up to twice each.

Proposed flow — automated, no live agent

Stage by stage

  1. Order marked delivered trigger
    The moment an order flips to delivered, its order_id and customer reference are handed to the calling flow — this is what starts the clock.
  2. Look up the bridge number Urban Piper
    The order is searched in Urban Piper, which returns the customer's masked/bridge number for that order along with an OTP — the credential that authorises using the number for this call. The OTP is single-use and scoped to that one order_id; it can't be reused for a retry or any other call. For Zomato specifically, this must be requested before the order is dispatched — the option disappears once it's marked dispatched.
  3. Order dispatched kitchen event
    The kitchen marks the order dispatched. This is the gate: Exotel does not place the call until this event has happened.
  4. Place the call Exotel
    Only once the order is dispatched, the masked number is handed to Exotel, which dials the customer directly. No agent is involved — this is a fully automated outbound call. If the order is delivered within 20 minutes, the call is placed on the 25th minute post-delivery — giving the customer time to actually eat before being asked to rate. Up to 2 call attempts (trials) are allowed per order.
  5. Play the rating ask 30-second clip
    On connect, Exotel plays a pre-recorded clip nudging the customer toward a 5-star rating: "Hi this is Anil, calling from Olio Pizza. We just dispatched your order hot & fresh. Hope you like it. Please rate us 5-star, this will help us serve you better. Thank you." Proposed: the 1st attempt stays ratings-only like this; a 2nd attempt (retry) adds a short open-ended feedback prompt, since the customer has had time to actually eat by then — see Open Queries.
  6. Log the outcome Google Sheet
    The result is written to a Google Sheet — picked up / no answer / cut, duration, timestamp. A no-answer only closes out and logs after the 2nd attempt also goes unanswered; a pickup on either attempt logs immediately as connected. That's what rolls up into an overall success-rate view.

Success-rate metrics

Connect rate
connected ÷ total dialed
How many customers picked the call — the share of calls a customer actually picked up.
Full-play rate
clip_played_full ÷ connected
Of the calls that connected, how many stayed on long enough to hear the full rating ask before cutting.
